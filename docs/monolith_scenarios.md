# Полный перенос плагинов и сценариев монолита

Перенесены все восемь плагинов и связанные backend-сценарии.
Эталон — исходники old_monolit; runtime нового приложения их не импортирует.
Проверки выполняются локально с одним агентом. Платные провайдеры без разрешения не вызываются.

| Плагин монолита | Требуемое поведение | Текущее положение |
| --- | --- | --- |
| input | Файловый вход, проверка типа audio/video/pdf/text/image/any | Реализован 1.0.0; MIME из авторизованного FileInfo RPC, потоковые bytes/UTF-8/metadata. Docker-сценарии текстового и видеовхода, BOM и отказа по MIME прошли |
| media_converter | Аудио/видео → m4a/mp3/wav, bitrate, sample_rate, длительность | Настоящий FFmpeg проверен для трёх форматов; Docker WAV/MP4 → M4A → S3 проверен независимым ffprobe. Версия 1.1.0 сохраняет вход во временный файл и отдаёт выход частями; проверен WAV 19,2 МБ |
| speech_to_text | Разбиение по времени и размеру, транскрипция, язык, артефакт | Версия 1.1.0: временный файл, MP3-части по времени/размеру, последовательная транскрипция и артефакт. Docker: 61 секунда → три HTTP-запроса; предел частей и ошибки без частичного артефакта проверены unit-тестами |
| prompt_selector | Чтение доступного промпта, шаблон и переменные | Проверены unit/gRPC и настоящий Docker DAG с библиотекой промптов |
| llm_request | Модель, temperature, max_tokens, timeout, переменные, ответ | Проверены переменные, лимиты, ошибки и Docker DAG через HTTP-fixture. Реальный платный LLM не вызывался |
| text_to_md | Создание конспекта через LLM, prompt, max_chars, style | Добавлен 1.0.0; unit и сквозной text file → input + prompt_selector → LLM → Markdown в S3 проходят. Форматтер 0.1.0 сохранён |
| text_to_latex | Генерация LaTeX, классификация предмета, промпты | Реализован 1.0.0; классификация, снятие code fences, артефакт и Docker-цепочка до PDF проверены с offline HTTP-fixture |
| latex_to_pdf | Настоящая компиляция, ограниченные попытки исправления через LLM | Реализован 1.0.0; реальный pdflatex, ремонт после ошибки, отказ без ремонта, бесконечный TeX/timeout и кириллица проверены в Docker. PDF прочитан независимым pdftotext |

Сценарии из old_monolit/scripts/init_data.py:

1. audio/video → input → media_converter → speech_to_text + prompt_selector → Markdown;
2. audio/video → input → media_converter → speech_to_text + prompt_selector → LaTeX → PDF;
3. text file → input + prompt_selector → Markdown.

Также проверены отдельный LLM-запрос с переменными, ветвление DAG, ошибки входов и провайдера,
отмена с очисткой контейнеров, повторный запуск/retry и восстановление после прерывания.
Успешный узкий тест не закрывает всю строку этой таблицы.

Внешний HTTP провайдера можно заменить явным локальным тестовым сервером для проверки
транспорта и пайплайна. Такая проверка не доказывает качество реальной модели или
доступность платного сервиса. Медиа и PDF должны создаваться настоящими FFmpeg и TeX.
Формат транскрипции сверён с [официальным API Polza](https://polza.ai/docs/api-reference/audio/transcriptions):
JSON с `model`, base64/data-URL в `file`, `response_format=json` и необязательным ISO-кодом
`language`. Для автоматического определения языка поле `language` не отправляется.

Проверка переноса через локальные сервисы:

```sh
python3 infra/local/backend.py up --test-provider
python3 infra/local/backend.py scenarios
```

Режим явно заменяет внешний провайдер HTTP-сервером на numeric loopback внутри
контейнера provider. Он не пересылает запросы наружу. `scenarios` отказывается
работать без этого режима. Проверены selector/LLM, текстовый Markdown, медиа,
LaTeX/PDF и перечисленные отказы. Аудио и видео → конвертация → STT →
ветвление на Markdown и LaTeX/PDF, разбиение аудио и вход 19,2 МБ проверены.
Pause/resume, ограниченные автоматические попытки, ручной retry и восстановление
после SIGKILL проверены командой `recovery` на тех же локальных сервисах.

Версии плагинов нужно сохранять раздельно: существующий форматтер text_to_md@0.1.0
не должен незаметно менять поведение на LLM-конспектирование. Кодген теперь
поддерживает выбор `name@version` и отклоняет неоднозначное имя.

Нативные зависимости задаются через `plugin.system_packages`; кодген включает их
в обычный и controlled Dockerfile. Пустой список не меняет каноническое представление
старых манифестов. LaTeX-компилятор запускается без shell escape, с ограничением времени
и отдельным окружением; таймаут и отмена завершают группу его процессов.

Для media_converter@1.1.0 вход ограничен 256 МиБ, выход — 64 МиБ; выходные кадры
не превышают 64 КиБ. speech_to_text@1.1.0 принимает до 256 МиБ, отправляет части
до 7 МиБ (меньше предела provider 8 МиБ), ограничивает количество частей и общий текст.
Нативные FFmpeg-зависимости новых версий объявлены в манифестах. Зарегистрированные
версии 1.0.0 сохранены отдельно. Runtime вызывает необязательный `on_cleanup` после
успеха, ошибки и отмены; временные файлы закрываются и удаляются.
Локальный агент задаёт sandbox 1 ГиБ RAM и 384 МиБ tmpfs через ограниченные настройки
кодогена; параметры workflow не могут менять эти лимиты.

```sh
python3 infra/local/backend.py seed
```

Команда добавляет два общих промпта и пять графов: audio/video → Markdown/PDF,
text → Markdown. Существующие записи сохраняются. Для запуска нужно загрузить файл,
скопировать выбранный граф через ForkWorkflow и передать `initial_inputs.file` с ID
этого файла. В готовых графах закреплены версии плагинов; фронтенд не требуется.
Все пять графов проверены запуском пользовательских копий в Docker; общие графы
после исполнения сверены с исходными. Повторный seed переиспользовал те же ID.

В долгой проверке найден и исправлен кэш межсервисных JWT: срок хранения ограничен
`exp` выданного билета и проверяется и по wall clock, и по monotonic clock. Регрессионный
тест покрывает скачок времени после приостановки VM и более короткий TTL от TAS.

## Управление исполнением и восстановление

```sh
python3 infra/local/backend.py recovery
python3 infra/local/backend.py migration-race
python3 infra/local/backend.py replicas
```

`recovery` намеренно вызывает ошибки локального HTTP-fixture и перезапускает только
контейнер оркестратора через SIGKILL. Проверены автоматическая попытка после 503,
исчерпание двух повторных попыток узла, ручной RetryNode, pause/resume во время HTTP
и продолжение после потери процесса. Число запусков завершённого источника сверяется
по БД: один. Итоговый текст скачивается из S3 и сравнивается с ожидаемым.
Старые контейнеры проверяются по журналу попыток и удаляются.

В api_execution доступны Pause, Resume и RetryNode. Pause сохраняет PAUSED и отзывает
аренду и право отчётов. Незавершённые активные узлы становятся PENDING с сообщением о паузе;
остановленные контейнеры не отображаются как PROCESSING.
Resume сохраняет завершённые узлы, обновляет credential владельца
и ставит исполнение в очередь. Повторный Resume работающего исполнения ничего не отменяет.
RetryNode разрешён для FAILED: выбранный узел и его потомки выполняются заново,
незатронутые завершённые узлы сохраняются. Чужие исполнения скрыты; администратор не
может подменить credential владельца при возобновлении.

Выходные кадры сохраняются в PostgreSQL до передачи потребителям. Только после EOF,
проверки потоков и сохранения измерений узел получает COMPLETED/checkpoint_ready.
Новый владелец читает кадры страницами, сохраняя имена портов, последовательность и EOF.
Лимит узла — 1 ГиБ payload и 65536 кадров; это отдельные данные БД, помимо артефактов S3.
Данные сохраняются для истории и восстановления; автоматического удаления checkpoint пока нет.

Незавершённый узел запускается с начала. При падении после внешнего вызова, но до фиксации
завершения, этот вызов может повториться. Гарантия однократного внешнего эффекта не заявляется.
Pause не замораживает контейнер на инструкции процессора. Для старого исполнения без
checkpoint завершённого узла возвращается явная ошибка с предложением нового запуска.

Временные UNAVAILABLE/DEADLINE_EXCEEDED и ошибки связи с агентом имеют две повторные
попытки на узел с задержками 2 и 4 секунды, дополнительно к периоду планировщика.
Проверки доступа, параметры и ошибки компиляции автоматически не повторяются.
Коды backend-ошибок проходят через сгенерированные proxy/runtime без тел ошибок провайдера.
Метрики попыток и сохранения/воспроизведения кадров собираются средствами codegen.

Очистка запускается каждые 15 секунд. PREPARED отозванной аренды можно закрыть без Docker;
CREATED проверяется по точному attempt ID и меткам. CREATING без подтверждённого результата
не признаётся очищенным по одному отсутствию контейнера: такие попытки проверяются снова,
чтобы удалить контейнер, появившийся с задержкой. Очередь обходится с учётом времени последней проверки.

`migration-race` запускает два процесса миграций в отдельной временной PostgreSQL БД и
удаляет эту БД после проверки. Транзакционная advisory-блокировка отделена от соединения,
фиксирующего журнал миграций. URL подключения Alembic хранится в памяти.
`replicas` проверяет две реплики оркестратора на одном компьютере с одним агентом,
конкурентный идемпотентный Start, общий pause/resume и однократный запуск источника.
После проверки восстанавливаются одна реплика и исходный локальный порт.
