# Инфраструктура

Кодогенератор создаёт клиентский код и настройки.
PostgreSQL, Vault, Kafka, MinIO и системы наблюдения запускаются отдельно.
Файлы локального запуска находятся в infra.

| Модуль | Как работает сейчас | Ограничения |
| --- | --- | --- |
| gRPC | Генерирует сервер, клиентов, protobuf и interceptors | Полный запуск всех сервисов ещё не проверен |
| PostgreSQL | Async SQLAlchemy, пул соединений, транзакции и миграции | Миграции нужно применять отдельно; backup/restore не проверены |
| MinIO | S3-клиент; init-скрипт создаёт buckets | Использует протокол S3, не gRPC |
| Kafka | Producer/consumer и создание topics | Kafka — брокер событий, не RPC; это отдельный протокол |
| Config | gRPC-клиент получает feature flags и хранит кэш | Фоновое обновление работает отдельно в каждой реплике |
| TAS | gRPC-клиент получает сервисный ticket; interceptors передают и проверяют его | Доступы задаются конфигурацией проекта |
| Scheduler | Запускает периодические функции в asyncio | Cron заменяется часовым интервалом; DB хранит журнал, не распределённую блокировку |
| Vault | Генерирует AppRole policy и конфигурацию Vault Agent; секреты поступают в окружение | Локальный Compose использует dev-mode; это не production-настройка |
| Логи | Structlog, файл с ротацией; опциональная очередь отправки в Loki | Loki принимает HTTP; централизованная доставка не подтверждена сквозной проверкой |
| Трейсы и метрики | OpenTelemetry отправляет OTLP gRPC в Collector | Экспорт настроен без TLS; sampling требует проверки |
| Мониторинг | Collector направляет трейсы в Tempo, метрики в Prometheus; Grafana показывает данные | Наличие конфигурации не доказывает работу dashboards и alerts |

Сервисы приложения общаются по gRPC.
HTTP нужен внешним системам вроде Vault, S3 и провайдеров.
Клиентский HTTP API пока не реализуем.
