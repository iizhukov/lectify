# Что переносим из монолита

Эталон функций — old_monolit. Старый код нужен для сравнения;
новые сервисы не должны импортировать его при запуске.

Локально проверен путь: пользователь → файл/текст → создание и изменение workflow →
контейнеры плагинов на одном агенте → сохранённый результат в S3 → скачивание.
Сквозной сценарий также проверяет отмену, историю и отказ в доступе другому пользователю.
Запуск описан в backend_mvp.md. Восемь плагинов и пять готовых графов перенесены;
проверки и границы поведения описаны в monolith_scenarios.md.
Работают durable replay, pause/resume, ограниченные автоматические попытки и ручной retry.
Проверены SIGKILL и две локальные реплики с одним агентом.

Не завершены:
- profile, personal и правила использования LLM;
- промышленное управление агентами и сертификатами;
- работа нескольких хостов вне локального MVP;
- интерфейс и клиентский HTTP API (позже).

Наличие protobuf, манифеста или unit-теста не означает готовность сценария.
Нужны проверки реального запуска, хранения результата и отказов.
