# Перезапуск, подробности и логи исполнения

Внешний backend API — gRPC `execution.v1.ExecutionService`.
Между сервисами используются сгенерированные gRPC-клиенты.

## Полный перезапуск

`Restart(execution_id, request_key)` разрешён владельцу для COMPLETED, FAILED и CANCELLED.
Создаётся новое исполнение со ссылкой `parent_execution_id`, сохранённым графом,
закреплёнными версиями плагинов, параметрами и исходными входами. Все узлы исполняются
заново; checkpoint исходного исполнения не переиспользуется. Исходная история,
артефакты и состояние сохраняются. Изменение или удаление workflow не меняет сохранённый
граф перезапуска. Для RUNNING/PAUSED сначала нужно явно отменить исполнение.

Одинаковые execution_id/request_key у того же владельца возвращают один новый ID,
включая конкурентные запросы к разным репликам. Другой ключ создаёт новый запуск.
Новое исполнение получает свежий credential владельца. Администратор не может
подставить свой credential вместо владельца чужого исполнения.
Ссылки на внешние файлы и промпты проверяются заново через текущие права владельца.

`RetryNode` сохраняет прежний ID исполнения и повторяет выбранный узел и потомков.
`Restart` создаёт новый ID и выполняет весь граф с начала.

## Подробности

- `GetDetails(execution_id)` — состояние, ссылка на исходное исполнение, ID снимка в
  workflow_id, сохранённый граф, внешние входы и последнее исполнение каждого узла.
- `GetNodeDetails(execution_id, node_id, page_size, offset)` — сохранённые название,
  описание, параметры, входные привязки и рёбра, история попыток от новых к старым.
- Попытка содержит номер, ID, поколение аренды, состояние, время начала и завершения,
  измерения, артефакты, образ, идентификаторы агента и контейнера, объём и признак неполноты логов.
- `ListExecutions` содержит parent_execution_id для связи нового запуска с исходным.

Общий ответ возвращает последнюю попытку узла и has_more_attempts; полная история
читается через GetNodeDetails страницами до 100 элементов. Входные потоки описаны
ссылками на порты и исходными значениями initial_inputs; большие бинарные входы не
включаются в ответ подробностей.

## Логи

`GetNodeLogs(execution_id, node_id, attempt_number, after_sequence, page_size)`
возвращает до 100 событий и курсор next_sequence. Последовательности — курсоры общего
журнала, поэтому пропуски между номерами допустимы. Фильтрация выполняется на сервере
по исполнению, узлу и поколению конкретной попытки.

`DownloadNodeLog(execution_id, node_id, attempt_number)` возвращает текстовый .log
потоком кадров до 64 КиБ с последовательными номерами и явным EOF. Это снимок
доступных записей на момент начала запроса. Для живого журнала используется GetNodeLogs
с курсором или StreamEvents.

Сохраняются события начала/завершения попытки, SDK ReportLog, stdout/stderr процесса
плагина и диагностические файлы FFmpeg/ffprobe/TeX. Процессный stdout/stderr поступает
при остановке или завершении процесса; SDK-сообщения доступны сразу. Нативные логи
передаются до удаления временных файлов, в том числе при ошибке компиляции.
Сбор и очистка диагностики реализованы в шаблонах codegen, правила доступа — в приложении.

Ограничения: 1 МиБ сериализованных лог-событий на попытку, по 64 КиБ stdout/stderr
процесса и 64 КиБ диагностического файла на вызов инструмента; скачивание до 4 МиБ.
После достижения предела трубы процесса продолжают читаться, чтобы не блокировать
программу. logs_truncated/truncated указывает на ограничение, ошибку доставки или
возможную неполноту при аварийном прерывании; скачиваемый файл содержит отметку TRUNCATED.
Известные токены и приватные ключи, Bearer-заголовки и пароли в URL очищаются до
сохранения и разбиения сообщения на части.

История попыток хранится отдельно от состояния удаления контейнеров. Новое поколение
аренды закрывает незавершённую попытку как INTERRUPTED; pause/cancel сохраняются отдельно.
Восстановленный завершённый узел не получает новую попытку, поскольку его поток
воспроизводится из checkpoint.

Миграция 0007 добавляет связи перезапусков и историю попыток. Для старых запусков
попытки восстанавливаются по журналу контейнеров со статусом UNKNOWN: этот журнал
не доказывает результат каждой старой попытки. Ранее сохранённые SDK-события доступны;
ранее утраченные stdout/stderr восстановить невозможно.
Миграция 0008 добавляет индекс чтения событий по исполнению, узлу и попытке.

## Проверка на одном компьютере

```sh
python3 infra/local/backend.py up --test-provider
python3 infra/local/backend.py execution-details
```

Проверка использует реальные сервисы, PostgreSQL, Docker, S3 и TeX. Она проверяет
перезапуск COMPLETED/FAILED/CANCELLED, идемпотентность, сохранение графа после удаления
workflow, новую историю всех узлов и скачивание реальных диагностик компилятора.
Платные внешние модели не вызываются.
