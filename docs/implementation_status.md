# Состояние Lectify

Текущее направление — backend распределённой ETL-платформы. Название пока сохраняется.
Фронтенд — отдельная задача. Подробности текущей сборки: [backend_mvp.md](backend_mvp.md).

Добавлены агент Docker-хоста (`orchestrator_worker`), gRPC-транспорт запуска,
конфигурация подключения диспетчера к штатному оркестратору и получение схем
плагинов сервисом workflow. Есть внешние текстовые и файловые входы DAG,
текстовый/бинарный выход и потоковые выходы Python-обработчиков.
Локальный MVP ядра проверяется настоящим сквозным сценарием с одним агентом,
PostgreSQL, MinIO, штатной авторизацией, Docker-плагинами и Prometheus.

Плагины и backend-сценарии монолита перенесены и проверены локально.
Промышленный выпуск всего приложения ещё не завершён.

Сервисы общаются по gRPC. Клиентский HTTP API будет позже.
HTTP внешнего провайдера, Vault и S3 — отдельные инфраструктурные протоколы.

Работают отдельные сервисные сценарии и тесты: авторизация, файлы,
промпты, workflow, исполнения, provider и агент плагина.
Есть потоковый DAG, аренды задач в БД, отмена и запуск Docker-контейнеров.
Локально проверены создание и изменение DAG, идемпотентное исполнение,
текстовые и файловые входы/выходы, скачивание артефактов, отмена и изоляция данных.
Метрики собираются инструментами codegen через OTLP → Collector → Prometheus.
Проверены pause/resume, ограниченные auto-retry и ручной RetryNode, восстановление
после SIGKILL, две реплики оркестратора на одном компьютере с одним агентом и гонка миграций.
Завершённые потоки хранятся в БД и воспроизводятся без повторного запуска готового узла.
Есть полный Restart в новое связанное исполнение, подробности графа и попыток,
чтение логов страницами и скачивание .log. Stdout/stderr и диагностики FFmpeg/TeX
собираются средствами codegen. Контракты описаны в execution_details.md.
Проверки нескольких машин отложены.

Осталось:
- отделить интеграции Lectify от универсального кодогенератора;
- завершить промышленную выдачу и ротацию сертификатов (локальные создаются автоматически);
- завершить profile, personal и политику LLM;
- проверить работу нескольких хостов за пределами локального MVP;
- сделать клиентский HTTP API и интерфейс позже.

Telegram-мост удалён. Его автоматизация приостановлена.
Проверки запускаются через codegen CLI; сценарии Docker и PostgreSQL
находятся в tests/integration. Команды описаны в testing.md.
